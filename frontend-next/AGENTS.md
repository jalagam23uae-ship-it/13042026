## Testing layout

- **Unit and component tests** (`*.test.ts`, `*.test.tsx`) are colocated next to the source file they cover. They run under Vitest via `npm run test`.
- **End-to-end tests** live in `tests/e2e/` and run under Playwright via `npm run test:e2e`.

When adding a new test, place unit tests next to the code and reserve `tests/e2e/` for full browser flows.

## Folder structure

- `app/` — App Router route tree. Only reserved filenames (`page.tsx`, `layout.tsx`, `route.ts`, `loading.tsx`, `error.tsx`, `not-found.tsx`) and dynamic-segment folders should live in a route folder. Non-route component files should move to `_components/` inside the route folder, or to `components/` if shared across routes.
- `components/ui/` — primitive UI (shadcn-style). `components/layout/` — app chrome. `components/providers/` — React context providers. `components/common/` — shared cross-feature components. `components/dashboards/` — top-level dashboard screens. Feature-shared components go in `components/<feature>/`.
- `hooks/` — custom React hooks, one per file, named `use-*.ts`.
- `types/` — domain/UI TypeScript types only. **API types must come from `lib/api/schema.ts`** (generated by `npm run api:gen`) and must not be duplicated here.
- `lib/` — non-React utilities, API clients, auth helpers.
